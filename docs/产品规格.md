# 深圳骑行地图产品规格

更新：2026年10月8日。以用户最新纠正为准：核心是“抽象的直观”，用地标组织有原作微缩模型美感的骑行场景，不再做全量、等比例的深圳地图。

## 产品与视觉

面向公路车骑友，服务骑前选线。通过可识别的城市地标、山海关系与路线示意，找到想骑的区域；查看真实路线资料，导出轨迹或分享页面。界面与产品说明使用中文。

Factory 的视觉直接作为基准：固定等角正交视角、灰阶平面、细线、精细的小模型、克制的留白与城市日常动态。能直接复用原作代码的部分直接复用，不另写看起来相似的替代实现。深圳地标与骑行功能需要的内容才新增。

原作的关键在于用代码构建模型并手工编排场景。本项目同样区分两类内容：

- 具体：春笋、春茧、平安金融中心、市民中心、京基100等可识别地标，以及有作用的桥、港口和骑行道。
- 抽象：普通楼群、山体、海岸、树林和区际距离。保留方向、相邻关系与路线经过区域，压缩不帮助理解的空间，不逐栋复刻。

桌面初始展示全城，窄屏初始展示深圳湾近景，与原作按视口选取初始镜头的规则一致。春笋、春茧、人才公园、跨湾桥与红树林形成深圳湾片区。地点导航只移动镜头；点击模型只选择对象，镜头靠近由明确的卡片动作触发。

## 数据分工

画面里的微缩坐标不使用统一地理比例。屏幕路线是帮助认路的示意线，不承诺准确转弯，也不用于测距和导航。

真实骑行轨迹独立保存为WGS84原始道路节点，用于里程和导出。不得把地标连接线、屏幕圆角路径或动画路径写进轨迹文件。

首轮资料为33项全市路线候选，加8条已核对路网的连续轨迹，共41项。只对具备明确连续几何和通行依据的路线开放导出。其余候选可查看资料和所处片区，但不绘制假轨迹、不开放导出。

累计爬升缺少可靠依据时显示待核，不把它填为零。每条路线保留公开来源、发布日期、核实日期、路面和骑行限制。周末限制可实际阻止不适用路线的导出。

## 页面与操作

页面直接使用原作的画框、上下题注、顶部地点导航、左上纵向六个工具和按需出现的对象卡。工具顺序、尺寸、图标、快捷键、移动端断点和卡片位置按原作保留。删除另行设计的品牌标题栏、常驻路线侧栏、首屏推荐卡、天气按钮、罗盘和底部地区导航。

骑行资料使用同一张对象卡呈现。地标卡通向附近路线，题注上的骑行入口通向全路线集；筛选、通行限制、导出、分享和资料来源均在卡内。对象与路线选择不自动拉近；“靠近查看”或“查看线路”才调整镜头。手机沿用原作卡片移到底部、最高占场景55%的规则。

保留原作的车流、行人、列车、船舶、昼夜与天气氛围。这些属于模拟，不表示实时交通和天气。

全城地标视图、片区聚焦、平移与缩放用于认路和观赏。页面不做自由拼路、任意起终点自动规划、实时导航、账户和私人骑行记录上传。

## 当前实现约束

- 新的微缩运行时不加载全城道路、53万建筑轮廓、DEM或建筑分片。
- 先前获取的真实地图材料作为研究档案保留在工作区，退出页面静态资源目录，避免继续增加加载与构建资源。
- 沿用参考版本 `148758ae19a9b2201245485bf3619ab5e742f8f4` 的适用内核、材质、模型和基础样式。原仓库保留不动。
- 真实轨迹核验与微缩视觉验收分别记录，不能相互替代。

## 验证

实际在浏览器与原作同视口对照画框、题注、工具和详情卡，检查桌面全景、窄屏深圳湾、片区导航、悬停、选择、跟随、快捷键、昼夜与自动天气。需走完选线、详情、分享页面恢复、实际下载并回读轨迹，以及至少一种限制或缺数据路径。

视觉判断重点：第一眼能认出地标，路线关系清晰，建筑与树木有原作的微缩细节，画面没有无意义路网和大面积无效区域。构建成功或沿用原色板不能代替画面验收。

## 需求变更记录

早期“全深圳真实地理”的表达被实现为全量GIS地图。用户在看到方向后明确否定，指出资源大、无效区域多、缺少微缩模型美感。本规格按本次纠正替代“真实轮廓逐栋呈现”的旧要求；真实数据继续用于路线可信度，不再规定视觉必须一比一。

2026年10月8日，用户进一步要求 UI 与交互一比一对齐原作。仅复用等角色板不满足此要求；页面外壳和通用交互须直接从参考实现迁移，骑行内容装入原作卡片。场景内容继续遵循微缩地标原则，真实轨迹规则不变。
