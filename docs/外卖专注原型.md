# 外卖专注体验原型

本轮验证：用户专注时，一位骑手在真实深圳地图上自动送单，能否产生持续陪伴、打工得失与城市探索的体验。

这是独立试玩页面，使用既有 Next.js 项目、Factory 界面样式、字体、深圳建筑与地形。存放在 `prototype/shenzhen-delivery-focus` 分支，不替换原有骑行选线入口。页面路径为 `/prototype/delivery/`。

## 已确认规则

- 用户选择专注时间，系统动态安排连续配送行程；45分钟至少安排两单。
- 系统自动派单、规划路线、处理模拟中的等餐、天气与路况事件。专注期间没有必须响应的操作。
- 收入、超时扣费与评分有得失；模拟事件不延长用户设定的专注计时。
- 下一趟从上次收工位置继续。主动提前收工结算已完成订单，取消未完成订单并影响评分。
- 关闭页面不会终止配送；以持久化的开始时间和真实经过时间恢复进度，完成后只结算一次。
- 收入用于车辆、装备和住处；配送足迹用于探索片区、地标和熟客记录。
- 订单与经济均为虚构游戏数据，深圳地图与可行走路网复用现有来源。
- 正常专注使用实际分钟；快速试玩明确标注加速，并使用独立试玩存档。

## 模块边界

1. `lib/delivery/`：道路寻路、配送计划、时间派生进度、本地存档、幂等结算和消费。依赖真实时间戳，不依赖网页是否保持打开。
2. `scene/delivery.ts`：消费 `DeliverySceneState`，复用原作模型和材质绘制外卖骑手、餐箱、路线、取送点；不拥有计时和钱包。
3. `components/DeliveryPrototype.tsx`：同一画框内的开工、当前订单、结算、养成和探索。沿用 Factory 导航、控件、卡片及字体。

先比较“每帧累计计时”与“持久化时间戳派生行程”两种方案。本轮选择后者：网页关闭后无需后台进程仍可恢复；事件和订单结果在生成时固定，刷新不会重新掷骰子。正常存档与试玩存档各自拥有唯一活动行程，重复恢复不会重复奖励。

## 验证目标

在实际浏览器从开工走到结算并购买装备；检查45分钟订单数、路线连续性、关闭后恢复、重复刷新不重复结算、提前收工与下一趟位置延续。回看桌面及手机尺寸截图，复查原骑行入口。原型不新增测试套件，所有实际结果与未验证项在本文件末尾补记。
