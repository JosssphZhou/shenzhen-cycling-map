# 骑手与加载优化：测量约定

待验证的主张：生产构建在相同网络、CPU 与画面条件下，更早呈现可见的骑手及三维城市，并更早加载完整近景建筑与地形。保留原始地理和建筑形状，不以减少真实城市内容换取时间。

基准为本轮修改前的 33a3689 静态导出副本。新旧两侧均使用相同 gzip 静态服务器；不把开发服务器编译时间计为旧版渲染性能。每侧五次，交替运行。HTTP 缓存禁用；操作系统文件缓存和 GPU 缓存不清除，所以不声称整台机器冷启动。

预定浏览条件：桌面 1440×1000，20 Mbps 下载、40 毫秒延迟、CPU 四倍减速。以导航起点为零；逐帧记录骑手和首个真实建筑分块完成绘制的时间，以及相机到位、可见建筑分块完成、贴岸地形完成的时间。检查真实绘制调用、可见建筑数量、请求失败和页面错误。另做一次不计入结果的 CPU 采样定位耗时。

优先排查：全城 JSON 传输和解析；主线程建筑挤出和道路三角化；每个精细分块到达后重复重建概览；开发模式编译。分别通过资源时间、CPU 采样、静态几何缓存和生产预览核对。

本轮不新增测试套件。运行真实浏览器复现、几何生成核对、构建和类型检查；原型数据及用户存档格式不变。
