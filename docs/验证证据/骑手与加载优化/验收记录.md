# 骑手与首次加载优化验收

美团黄、饿了么蓝两套电动踏板车骑手已接入，可在开工卡和“我的”切换。制服、头盔和餐箱都有品牌字样；车辆具有封闭车身、宽踏板、小轮胎、坐垫、车灯和后视镜。平台选择单独保存，不修改配送经济存档。骑手在独立前景中绘制，保留车体内部深度；密集楼群不会遮住骑手，实际指针点击也能优先选中它。

本地生产入口：<http://localhost:3701/prototype/delivery?mode=demo>。保留原Factory字体、菜单、画框和城市构模方式。

## 真实加载对比

基准33a3689，最终运行代码a73c7e5。两侧都是生产导出，使用同一gzip静态服务器。桌面1440×1000、DPR1、20Mbps下载、40毫秒延迟、CPU四倍减速；每侧先预热一次，再交替记录五次。HTTP缓存禁用，操作系统和GPU缓存保留。共享主机还有其他工作，没有停止其他项目；正式测量前30核机器负载为7.75、10.17、10.42。

首个街区的时间差小于本机波动，不单独宣称提速；完整近景等待减少54.5%。十次正式记录均成功，无页面异常或HTTP失败；两侧都实际显示45个精细街区、33,804栋建筑。新版正常路径没有请求原全城JSON、原地形JSON或原街区JSON。旧版三角面统计为非有限数，未用它比较几何数量；以实际绘制、街区建筑数、截图及原几何核对确认内容。

未计入结果的CPU采样定位到道路几何生成、三角化、概览重建和绘制成本；旧版逐批等待街区队列也增加了等待。新版提前生成原几何，按视野加载，首帧直接落在骑手附近，街区完成后立即补充下一片。轨迹复用缓冲区，途中没有反复重建整条线。当前等待仍包含数据传输、解码和首次GPU提交。

这不是下载量下降的结论。已完成请求的transferSize中位数为8.80MB、11.22MB，不包含取消请求尚未完成的部分传输；几何缓存用更多下载字节换取更少的主线程计算。第一版缓存曾需约17MB，本轮无损字典编码把全套缓存gzip体积从141.83MB降至72.45MB。极弱网和真实手机首载速度尚未测量，手机只做了429×928布局和交互核对。

## 内容和行为核对

- 865份缓存解码后与原缓存完整字节一致，包含Float32位序、层级、变换和材质键。负数和负零也保持一致。804份采用新字典编码，61份小文件保留原编码。生成记录与逐文件SHA见`public/data/fast-city/build-statistics.json`。没有修改原城市JSON、原道路连接或GPX。
- 桌面实际切换并回看两套电动车近景；平台选择前后的正常、试玩存档逐字相等。
- 实际启动45分钟的90秒试跑，安排两单。暂停城市后骑手继续移动，途中`routeBuilds`始终为1；手机没有横向溢出，只有一个canvas。
- 离开配送页面后再回来，自动结算两单、实收23.18元；再刷新，钱包和账单数不变，品牌和终点位置恢复。正常专注存档没有被试玩修改。
- 原骑行入口、盐田海岸、梧桐山地形和全景实际打开并截图回看。全景显示10,619个概览建筑，另有5个专用地标模型；原来源计数10,624不变。
- 阻断快速索引后实际回退原地图，仍绘出真实建筑。再同时阻断原地图，显示中文失败与重新载入按钮；解除阻断并点击后恢复几何缓存和建筑，保持一个canvas。
- 最终生产入口现有两份存档的SHA256指纹保持一致，未重置钱包或历史账单。
- 最终生产构建、TypeScript检查通过。没有新增或修改测试文件；采用实际浏览器流程、临时加载测量器及资产生成时的精确核对。临时测量器位于任务工作目录`work/benchmark-delivery-load-overlay.mjs`。
